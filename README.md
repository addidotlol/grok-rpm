# grok-rpm

Automatically tracks [Grok Bot](https://x.ai/bot) releases, converts the official Debian package to RPM (**including the dependency list**), and maintains a `dnf`-compatible RPM repository — all driven by a small Go app running on GitHub Actions.

> Unofficial. Not affiliated with xAI / Cursor. Grok Bot is proprietary; this repo only repackages the official `.deb` at build time.

## How it works

Upstream publishes Grok Bot under the update-service app name **`sand`**:

- `GET https://api2.cursor.sh/updates/api/update/linux-x64/sand/0.0.0/stable`
  → `{"version":"0.44.0","url":"https://downloads.cursor.com/grokbot/stable/<40-hex>/linux/x64/..."}`

The 40-hex path segment is the **build ID**. The `.deb` URLs are reconstructed from it:

- `.../stable/<build>/linux/x64/grok-bot_<ver>_amd64.deb`
- `.../stable/<build>/linux/arm64/grok-bot_<ver>_arm64.deb`

(`https://cursor.com/download/bot` is scraped as a fallback. Note the page also lists `Grok_Bot_<ver>.rpm` links, but those currently return HTTP 403 — which is why `.deb` → `.rpm` conversion is still needed.)

The Go app (`cmd/grok-rpm`):

1. **waits** — `daemon` polls the feeds on an interval; `sync --once` does one iteration (what CI runs).
2. **downloads** the official `.deb`(s).
3. **converts** each `.deb` to RPM:
   - parses `DEBIAN/control` with a built-in ar/xz/tar reader (no `dpkg` required),
   - translates every `Depends`/`Recommends` entry via `internal/depmap` (e.g. `libgtk-3-0` → `gtk3`, `libnss3` → `nss`, `libasound2t64 | libasound2` → `alsa-lib`),
   - stages the payload, ships the `/usr/bin/grok-bot` symlink the `.deb` only creates in `postinst`, sets `chrome-sandbox` to 4755, and builds with `rpmbuild -bb`.
4. **makes a repository** — writes `repo/*.rpm` + `repo/repodata/repomd.xml` (+ `primary`/`filelists`/`other`). Uses `createrepo_c` when present, otherwise the built-in generator (verified with `dnf repoquery`).

## Repo layout

```
cmd/grok-rpm/          CLI (check/download/convert/repo/sync/daemon)
internal/feed/         upstream version discovery
internal/deb/          .deb control + payload reader
internal/depmap/       Debian -> Fedora dependency map
internal/rpmbuild/     spec rendering + rpmbuild invocation
internal/repo/         repodata generator + .repo file
internal/state/        VERSION/BUILD_ID persistence
repo/                  built RPMs + repodata (dnf baseurl) + grok-bot.repo
.github/workflows/sync.yml   daily + manual sync, release on new version
```

## Use the dnf repo

```bash
# repo/*.rpm live in Git LFS (they exceed GitHub's 100MB blob limit);
# raw.githubusercontent.com resolves LFS, Pages would only serve pointers.
sudo curl -L -o /etc/yum.repos.d/grok-bot.repo \
  https://raw.githubusercontent.com/<owner>/<repo>/main/repo/grok-bot.repo
sudo dnf install -y grok-bot
```

`grok-bot.repo` is generated by the app (`--baseurl` flag); the workflow points it at `raw.githubusercontent.com`. No Pages setup needed.

Contributors need LFS once: `git lfs install && git lfs pull`. Heads-up on
quotas: LFS objects stay on the server even after old RPMs are pruned from
git, so watch the 1GB free storage/bandwidth and compact history if it
fills up.

## Run locally

Requires Go 1.23+ and `rpmbuild` (`dnf install rpm-build` / `apt install rpm`).

```bash
go run ./cmd/grok-rpm check
go run ./cmd/grok-rpm sync --once --arch amd64 --state-dir . --repo-dir ./repo
dnf repoquery --repofrompath=t,/repo --repo=t --qf '%{name} %{version} %{arch}'
```

Long-running watcher:

```bash
go run ./cmd/grok-rpm daemon --poll-interval 6h --repo-dir ./repo
```

Single conversion (shows dep translation):

```bash
go run ./cmd/grok-rpm convert --deb grok-bot_0.44.0_amd64.deb --outdir ./repo
rpm -qpR repo/*.rpm
```

## GitHub Actions

`.github/workflows/sync.yml` runs `check` → per-arch `build` → `publish`:

- **schedule** daily (`17 6 * * *`) + **workflow_dispatch** (`version`, `arch`, `force`) + push on Go/workflow changes.
- `check` resolves the upstream version/build and skips the rest when `VERSION`/`BUILD_ID` already match (unless `force`).
- `build` is a matrix: `amd64` on `ubuntu-latest`, `arm64` on `ubuntu-24.04-arm`. **Each arch must build on a native runner** — rpmbuild cannot cross-build (`--target aarch64` on x86_64 fails with `No compatible architectures found for build` because Ubuntu's rpm lacks that platform). `sync --arch all` on one machine hits the same wall; run one arch per machine or use the matrix.
- `publish` merges the RPM artifacts, regenerates repodata (`repo --keep 2`), commits `VERSION`, `BUILD_ID`, `repo/`, and creates GitHub Release `v<ver>` with the RPMs.

Pruning: `--keep 2` retains the 2 newest RPMs per arch so git history stays bounded. Version state lives in `VERSION`/`BUILD_ID` (same convention as other Grok Bot Linux ports).

## Dependency mapping

`internal/depmap` covers the real Grok Bot 0.44.0 list:

| Debian | RPM |
|---|---|
| libgtk-3-0 | gtk3 |
| libnotify4 | libnotify |
| libnss3 | nss |
| libxss1 | libXScrnSaver |
| libxtst6 | libXtst |
| xdg-utils | xdg-utils |
| libatspi2.0-0 | at-spi2-core |
| libuuid1 | libuuid |
| libsecret-1-0 | libsecret |
| libasound2t64 \| libasound2 | alsa-lib |
| libgbm1 | mesa-libgbm |
| libxkbcommon0 | libxkbcommon |
| libdrm2 | libdrm |
| libappindicator3-1 (Recommends) | libappindicator-gtk3 (Recommends) |

Unmapped names are kept verbatim and reported (`warning: unmapped ...`) so the spec never silently drops a requirement. Debian-only `postinst` work (apt source registration, AppArmor profile) is intentionally omitted; `%post` handles `chrome-sandbox` perms, `update-desktop-database`, and icon cache.
